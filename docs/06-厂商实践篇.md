# 06 · 厂商实践:安卓软件的底栏液态玻璃都是怎么做的

> 逆向样本:酷安 v16.6.2(`com.coolapk.market`,116MB,单 dex 102MB,R8 混淆)。
> 方法:unzip → dex 字符串/类名/Kotlin 源文件名提取 → AGSL shader 逐字比对 → 公开资料交叉验证。

## 一、先说总谱系:大家都站在同一批开源实现上

酷安 dex 中的 lens 折射 shader(含七段采样光谱色散)与 **Kyant0/AndroidLiquidGlass 谱系逐字一致**;
NPatch 收录的版本(`../android/compose-miuix/liquid/Lens.kt`)与酷安的两个 shader
(`ROUNDED_RECT_REFRACTION` / `..._WITH_DISPERSION`,uniform 名、circleMap、1/3.5 与 1/7 加权全部相同)。

| 实现 | shader 来源 | 说明 |
|---|---|---|
| 酷安 16.x | Kyant0 谱系(逐字一致) | 自研工程化封装 |
| NPatch | miuix-kmp blur(同谱系) | 文件头注明 "Adapted from compose-miuix-ui IosLiquidGlassNavigationBar" |
| WeKit / InstallerX-Revived | 同上 | NPatch 底栏的移植来源 |
| QWEA0/Liquid-Glass-Android | 同原理 SDF | 面向 View 体系的开源库 |
| chrisbanes/haze | AGSL 模糊(dex 中可见其 issue #520 注释) | 酷安也带了 haze,用于磨砂 |

**结论:行业标准做法 = `RuntimeShader(AGSL) + 圆角矩形 SDF 位移折射`,shader 代码在社区里同源流转,差异化全在工程封装与交互细节。**

## 二、酷安 v16.6.2:目前国产 App 里最完整的自研体系

### 逆向可见的架构(26 个 Kotlin 源文件 + 独立资源库)

```
com.coolapk.market.widget.compose.liquid        ← 实现包
com.coolapk.liquidglass(R$color/id/string/style)← 独立资源库(AAR 级拆分)
├─ 能力层   LiquidGlassCapability               ← 能力对象,可组合/回退
│                                            (dex 中有 (Cap, Cap) -> Cap 的协商签名)
├─ 宿主层   LiquidGlassHost / CoolapkLiquidGlassHost / LegacyViewLiquidHost
│           LiquidGlassPageScaffold / ChromeRegionSlot / LiquidGlassTopBarSlot
│           ← 页面级"玻璃宿主":老 View 页面经 LegacyViewLiquidHost 接入
├─ 底栏     LiquidBottomNavigationBar / LiquidGlassTabPanel / CoolapkLiquidBottomBarPlacement
├─ 采样管线 LiquidGlassChromeSampling
│           LiquidTabCaptureChannel / LiquidTabCaptureSourcePolicy
│           LiquidTabCaptureRecordingPolicy / LiquidTabBackdropRendererPolicy
│           ← 比 Kyant0 的 rememberLayerBackdrop 更工程化:采集"通道"+三种策略解耦
├─ 动效     LiquidTabGestureClaimAxis(手势仲裁)/ MotionPhase / MotionState / HighlightMode
│           internal/DampedDragAnimation / DragGestureInspector / InteractiveHighlight
│           ← 与 NPatch 同款阻尼拖拽 + 交互高光(同谱系再验证)
├─ 边缘/模糊 LiquidGlassEdge / EdgeMode / ProgressiveBlurPath(LiquidGlassProgressiveBlur)
│           ← 渐进模糊:靠近边缘模糊半径渐变,底栏"融入"内容而非硬切
├─ 表面     LiquidGlassSurface / Shapes / Style / Styles / Controls / Interaction
└─ 业务应用  LiquidFeedDetailActionBar / LiquidProductNodeActionBar /
            LiquidSecondHandDetailActionBar / LiquidNodeFloatingActionButton
            ← 不只底栏:详情页操作栏、商品栏、FAB 全部玻璃化
```

资源键(arsc):`liquid_bottom_navigation_height`、`liquid_bottom_anchor`、
`liquid_glass_legacy_backdrop_host`、`liquid_home_structure_compose/demo/root`;
还有内置演示页 `LiquidBottomNavigationDemoActivity`、`LiquidHomeStructureDemoActivity`
(`@ExperimentalLiquidGlassCatalogApi` —— 工程内做效果目录/回归)。

### shader 取证(dex 字符串池)

- `uniform shader content` + `sdRoundedRect` + `circleMap` + `refractionHeight/Amount` —— 非色散版
- `uniform float chromaticAberration` + `dispersionIntensity = CA * (cx·cy)/(hx·hy)` + 七段采样 —— 色散版
- 65 处 `RenderEffect`、9 处 `RuntimeShader`、`createBlurEffect`/`createRuntimeShaderEffect`
- haze 的高斯模糊 shader 连 `chrisbanes/haze/issues/520` 注释都带(注释是 shader 字符串的一部分)

### 公开版本信息(与逆向吻合)

- 16.2.4+ 更新日志:上线「液态玻璃」「沉浸光感」**悬浮底栏**(首页/文章页/帖子页),
  数码、话题详情页改为液态玻璃悬浮底栏,底栏随滚动收起;
- 设置里有「液态玻璃」相关文案(arsc 中可见);桌面版 coolapk-desktop 提供总开关(默认关);
- 滚动时顶栏/底栏自动收起 —— "玻璃只在需要时出现"的取舍。

## 三、腾讯系(QQ 等):跨平台框架走「封装原生 + 明确降级」

[Kuikly](https://kuikly.tds.qq.com/API/components/liquid-glass.html)(KMP 跨端框架,QQ 系主力)2025-09 率先适配:

- **iOS 26+**:直接封装原生 `glassEffectIOS()`(UITabBar/UIGlassContainerEffect 自带玻璃)——
  组件 `LiquidGlass { }`,属性 `glassEffectInteractive / glassEffectTintColor / glassEffectStyle(REGULAR|CLEAR)`;
- **Android / 旧系统**:`PlatformUtils.isLiquidGlassSupported()` 检测 → 降级为普通 View + 灰背景,子组件不变;
- **使用准则(值得抄)**:玻璃**只用于浮层**(TabBar、导航栏、工具栏、悬浮按钮、面板),
  不用于列表项/卡片等内容层;26+ 上 boxShadow 会被系统玻璃自带的阴影替代。

即:跨端框架不自己写折射,**iOS 白嫖系统,安卓降级灰面** —— 与自研 App(酷安)路线相反。

## 四、ROM 厂商:系统设计语言跟进(底栏玻璃由启动器/框架提供)

2025-2026 大版本都在向"类液态玻璃"靠拢(公开资料):

| 系统 | 动向 |
|---|---|
| vivo OriginOS 6 | 「液态玻璃式」设计为核心,空间体系 2.0、**动态透彩材质**(色彩随内容实时变化) |
| OPPO ColorOS 16 | 与 OriginOS 6 直接对标的流畅度/设计竞争;可设置微信、输入法的玻璃效果 |
| 小米 HyperOS 3 | 最后一批"上岛",超级岛成熟;视觉上采用玻璃质感卡片 |
| 后续(OriginOS 7 等) | 被评价为"最直白"的液态玻璃尝试 |

ROM 层的玻璃供的是**系统 UI/启动器底栏**,三方 App 拿不到 API —— 这正是酷安们要自研的原因。

## 五、其他 App 与社区

- **Apple Music 安卓版**:跟进玻璃风格(苹果自家的"逆输出");
- **B 站/QQ/抖音**:底栏玻璃化讨论集中在社区复刻(B 站「安卓液态玻璃底栏 2.0/3.0」7 万+播放),
  正式版多以"悬浮底栏 + 模糊"渐进试水,真折射少见 —— 成本与机型碎片化是主因;
- **社区组件**:QWEA0/Liquid-Glass-Android(View 体系 SDF 折射+物理色散+重力高光)、
  liquid-glass-compose 等;独立开发者实践:效果分档(关/轻/重)+「底栏玻璃模糊」设置项。

## 六、厂商做法 vs 本仓库方案:对照与可复用启示

| 议题 | 酷安(自研) | Kuikly(跨端) | NPatch(小团队) | 本仓库 |
|---|---|---|---|---|
| 折射 shader | Kyant0 谱系 AGSL | iOS 原生 / 安卓不做 | 同谱系 | 同谱系 |
| 能力协商 | Capability 对象可组合回退 | `isLiquidGlassSupported()` 单点判断 | SDK>=33 + isRuntimeShaderSupported | docs/05 分级表 |
| 采样架构 | CaptureChannel + 三策略 | — | rememberLayerBackdrop | 同 NPatch |
| 老 View 页面 | LegacyViewLiquidHost | 降级灰 View | — | QWEA0 库可参考 |
| 用户开关 | 总开关(桌面版默认关) | — | 设置开关 + Blur 档 | 建议三档:关/磨砂/全效果 |
| 浮层准则 | 底栏/操作栏/FAB/顶栏全玻璃化 | 只允许浮层 | 底栏 | 同 Kuikly 准则 |
| 滚动策略 | 底栏随滚动收起 | — | — | docs/01 第 5 节 |
| 效果回归 | 应用内 Demo/Catalog API | 官方 Demo | — | web 演示页 |

**四条可以直接抄的启示:**

1. **shader 不用自己发明** —— 全行业同源(Kyant0 谱系),把精力花在采样管线、能力协商、交互状态机上
   (酷安多出来的 20 个文件全是工程件,shader 只有两个);
2. **能力协商做成对象,不要做成 if-else** —— 酷安 `LiquidGlassCapability` 可组合/可回退,
   页面各自声明需要的能力,宿主统一裁决;跨端则学 Kuikly:`isSupported()` + 同构降级组件;
3. **玻璃只给浮层,内容层永远实底** —— 酷安与 Kuikly 准则一致;列表卡片上玻璃既费性能又毁可读性;
4. **给用户总开关 + 自动收起** —— 玻璃是装饰不是功能;滚动收起(酷安)同时解决遮挡与性能。
